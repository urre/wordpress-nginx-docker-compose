# CLAUDE.md

Guidance for Claude Code (and other AI agents) working in this repository.

## What this is

A **local development environment** for WordPress, orchestrated with Docker
Compose. It pairs the [Bedrock](https://roots.io/bedrock/) WordPress boilerplate
(in `src/`) with nginx, MariaDB, phpMyAdmin, Mailpit, Composer and WP-CLI. It is
meant to run on a developer's machine at `https://myapp.local` — **not** to be
deployed to production as-is.

## Architecture

Services are defined in [`docker-compose.yml`](docker-compose.yml):

| Service      | Image                                        | Purpose                                             |
| ------------ | -------------------------------------------- | --------------------------------------------------- |
| `nginx`      | `nginx:1.27-alpine`                          | TLS termination + reverse proxy to PHP-FPM          |
| `wordpress`  | built from [`Dockerfile`](Dockerfile)        | PHP-FPM 8.3 + WP-CLI (custom base image)            |
| `mysql`      | `mariadb:11.4`                               | Database; data persisted in `./data/db`             |
| `phpmyadmin` | `phpmyadmin:5.2`                             | DB admin UI at http://127.0.0.1:8082                |
| `mailpit`    | `axllent/mailpit`                            | Catches outgoing mail; UI at http://127.0.0.1:8025  |
| `composer`   | `composer:latest`                            | Runs Composer against `src/`                        |

- **nginx config** lives in [`nginx/default.conf.conf`](nginx/default.conf.conf).
  It is an **envsubst template** (`NGINX_ENVSUBST_TEMPLATE_SUFFIX=.conf`), so
  `${DOMAIN}` is substituted at container start from the `.env` value. Nginx
  proxies `.php` requests to `wordpress:9000` (PHP-FPM).
- **PHP config**: [`config/php.ini`](config/php.ini) and
  [`config/phpmyadmin.ini`](config/phpmyadmin.ini).
- **WordPress app**: [`src/`](src/) is a Bedrock project. Web root is `src/web`.
  Config is env-driven via [`src/.env`](src/.env) (Bedrock/phpdotenv), separate
  from the root [`.env`](.env) that Docker Compose reads.
- **Certificates**: `./certs` (git-ignored), generated by
  [`cli/create-cert.sh`](cli/create-cert.sh) using [mkcert](https://github.com/FiloSottile/mkcert).

## Two `.env` files — don't confuse them

- **Root `.env`** — read by Docker Compose. Keys: `APP_NAME`, `DOMAIN`,
  `DB_HOST`, `DB_NAME`, `DB_ROOT_PASSWORD`, `DB_TABLE_PREFIX`, `IP`.
- **`src/.env`** — read by Bedrock/WordPress. Keys: `DB_NAME`, `DB_USER`,
  `DB_PASSWORD`, `WP_HOME`, `WP_ENV`, salts, etc.

Both are git-ignored; `*.env.example` files are the committed templates.

## Common commands

```bash
# Generate a local TLS cert (run from ./cli, requires mkcert)
cd cli && ./create-cert.sh

# Install PHP dependencies (Bedrock) via the composer service
docker compose run --rm composer install

# Start / rebuild the stack
docker compose up -d
docker compose up -d --force-recreate --build   # after editing the Dockerfile

# WP-CLI (runs inside the wordpress container)
docker compose exec wordpress wp <command>

# Coding standards (PHP_CodeSniffer) — this is what CI runs
docker compose run --rm composer test   # equivalent to `phpcs` in src/

# Tail logs / stop
docker compose logs -f nginx
docker compose down
```

## Conventions & gotchas

- **`composer.json` ⇄ `composer.lock` must stay in sync.** CI runs
  `composer validate` and `composer install`, both of which fail on a mismatch.
  If you change `src/composer.json`, regenerate the lock with
  `docker compose run --rm composer update` in the same change.
- **Do not quote `DOMAIN` in the root `.env`.** nginx's envsubst inserts the
  value literally, so `DOMAIN='myapp.local'` produces an invalid cert path like
  `/etc/certs/'myapp.local'.pem`. Use `DOMAIN=myapp.local` (see issue #77).
- **PHP version is set by the base image** `urre/wordpress-nginx-docker-compose-image`
  (currently 8.3), not by the `Dockerfile` here. Bumping PHP means rebuilding
  that separate image *and* raising the `php` constraint in `src/composer.json`.
- **Apple Silicon / ARM:** the base image is now the official multi-arch
  `php:8.3-fpm` (`linux/amd64` + `linux/arm64`), so it runs natively on ARM
  (previously amd64-only under emulation; see issue #107).
- **Never commit** `.env`, `src/.env`, `certs/`, `data/`, or `src/vendor/` —
  they are git-ignored for good reason (secrets, keys, local DB, dependencies).
- **`src/` is Bedrock.** Follow Bedrock conventions: plugins/themes install to
  `src/web/app/`, WordPress core to `src/web/wp/`. Prefer Composer over manual
  edits inside `web/wp`.
